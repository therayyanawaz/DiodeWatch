## Appendix A, claim guardrail (now executable)

```bash
python -m scripts.checks.check_claims          # exit 0 = clean; wire into pre-commit
python -m scripts.checks.check_claims --json claims_scan.json
```

Six contracts run over every judge-facing surface: banned phrasings plus
absolute FPR claims with no denominator in their sentence (`BANNED`), the
documented metric table cells reconciled against the pinned metric artifacts
(`docs/evaluation/runs/*_metrics.json`, the committed copies CI reads, or a
local `results/ml/` copy when one exists, which the loader prefers), and, for any surface
quoting a benign-flow denominator, an explicit layer qualifier with that
corpus's benign-window alert count beside it (`FP_DENOMINATORS`). Three more
cover the claims that are *about this repo* rather than about detection: every
documented `N collected` / `N passed` is re-derived from
`pytest --collect-only` (`DOC_COLLECTED`), every documented
`python -m …` / `python …py` command must resolve to a file that exists
(`DOC_MODULE_CMD`), and every `github.com/<owner>/<repo>` link under this
account's own owner must be the repository remote `origin` points at
(`DOC_REPO_URL`), renaming the remote had left the README's clone command
pointing at the stub that inherited the old name. Counts, commands and links
are checked on the exempt reference
docs too, their exemption only permits quoting banned wording. The headline
is no longer a mandated string to copy-paste: it fails when a number stops
matching its artifact, not when wording changes. Extend it there, not here.
